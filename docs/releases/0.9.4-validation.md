# Tauridium 0.9.4 release validation

Date: 2026-10-05. This patch corrects the Windows version-generator failure in
GitHub Actions job 111724473962. It preserves all earlier release tags and archives.
Final identities, artifact checksums and post-build evidence are recorded in the
external `tauridium-0.9.4-RELEASE-VALIDATION.md` handoff.

## Root cause and correction

The Node generator matched the Tauridium entry in `Cargo.lock` using LF-only
delimiters. Windows CRLF checkouts failed before the Nix-documentation tests could
exercise the already-fixed UTF-8 reads. Captured subprocess stderr was missing
from their failure diagnostics.

The generator now matches LF or CRLF and preserves every lockfile byte outside
the Tauridium version. A missing package entry still fails, including when other
files already have the requested version. Already-synchronized runs succeed.
Test failures include the captured Node output. No global encoding setting,
Git newline workaround, dependency update or application behavior change is used.

Thirteen focused integration-harness tests pass with Node 24 and Node 22.23.3,
the latter matching the failing CI runner. New cases verify LF/CRLF lockfile
preservation, byte-for-byte idempotence of all generated files and missing-entry
rejection. CRLF cases also run under the simulated CP1252 default; the original
Unicode decoding negative control is retained. The added CRLF tests were first
run against the old generator and reproduced its failure before the fix.

## Limits and publication

Windows native execution is unavailable at the WSL interop boundary. CRLF and
CP1252 regression fixtures are not a Windows native build. Full Windows/WebView2,
installer and ARM execution remain remote CI/manual gates; local ARM checks are
evaluations only. No fresh full Flatpak-builder, macOS, authenticated-service,
hardware-GPU/Wayland or Flathub-publication run is claimed.

Tests use isolated profiles and do not activate the host NixOS/Home Manager
configuration. The Linux runtime is a real Nix-linked executable, not an AppImage
or a bundled Nix closure: use the matching `nix develop` environment or prefer the
wrapped flake package. A source-only Windows build handoff does not claim a
Windows runtime. No GitHub push/publication is performed; push master, wait for
full pipelines, then push **v0.9.4**. Earlier tags must not be moved.
