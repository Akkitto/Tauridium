# Tauridium 0.9.5 release validation

This patch fixes the Advanced Settings overlay regression without changing
settings persistence, download destinations, sessions or dependencies.
Final executed gates, identities and checksums are recorded in the external
`tauridium-0.9.5-RELEASE-VALIDATION.md` handoff.

## Root cause and regression coverage

The download-notification checkbox used an unstyled `switch` wrapper instead of
the existing positioned `switch-control`, and omitted its thumb. Its absolutely
positioned decorative track therefore expanded to the window and intercepted
navigation. The correction restores the same compact control used elsewhere.
The adjacent selects and number input now use existing theme-aware styles. The
duration select also uses numeric option values to match persisted numeric
settings; its previous string values left the selected duration blank. Focused
negative controls reproduced both missing styles and mismatched option types.

Both structural regressions failed against the old implementation. The actual
0.9.4 production package independently reproduced the full-window pill after
opening Advanced; the negative screenshot is retained as diagnostic evidence.
Every switch is now checked for the positioned wrapper, track and thumb. This
portable frontend gate also runs in the normal Windows test workflow.

The new `just test-settings-ui` gate drives the actual production application
under isolated X11/D-Bus and temporary profiles. It checks General/Advanced
navigation, scrolling, notification toggle and option persistence, closing and
reopening Settings, in dark/light/OLED themes at 1100x900 and 760x600. Nix CI
runs it for both supported architectures and uploads screenshots and results.
It does not replace Tauri with mocked browser commands or access real accounts.

## Release process and limitations

Release gates retain exact pinned Rust formatting, warnings-as-errors compiler
matrices, supply-chain validation and all existing tests. Full-Git checkpoints
preserve progress around long production builds. Normal source/runtime/docs
archives require a clean exact annotated tag and reproducible ZIP packaging.
The Flatpak exact source commit is pinned after tagging to avoid self-reference.

Locally executed Linux rendering is not Windows/WebView2 or ARM execution.
Those remain remote CI/manual gates; a Windows source build handoff is not a
Windows executable. No fresh full Flatpak-builder, macOS, authenticated-service,
Wayland/hardware-GPU or Flathub publication is claimed. No remote push or
publication is performed. Earlier tags and artifacts are preserved.
