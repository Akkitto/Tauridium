# Tauridium 0.9.0 release validation

Date: 2026-10-03. This report distinguishes executed local gates from remote
platform checks and publication. The full assessment/plan was written before
implementation outside the repository under
`/home/akito/src/codex/tauridium-0.9.0-planning/`.

## Release scope

- Locked, source-built Nix packages/apps/overlay for x86_64-linux and
  aarch64-linux, using an explicit source fileset, real Cargo/npm dependency
  hashes, the production Tauri hook and GTK3 application wrapping.
- Compile-time Nix distribution without native self-updater or Flatpak sandbox
  policy. Ordinary Linux notifications/dialogs and existing profile behavior
  remain available. Updates settings explain Nix-managed updates.
- XDG session autostart uses stable `Exec=tauridium`, not an unwrapped store path.
  Atomic publication, custom/declarative entry protection, idempotence and legacy
  conflict detection are covered by five Rust regressions. Migration never
  silently deletes old native entries.
- Pinned 1.97.1 Rust/rustfmt/clippy development environment with Node 24 and
  native prerequisites. `just init` succeeds without host package/Rustup changes.
- Opt-in Nix recipes, installation/migration/development documentation, native
  architecture CI jobs, graphical smoke and isolated NixOS VM integration. Public
  release publication now requires the Nix job as well as all previous gates.

See [the Nix guide](../NIX.md) for commands and [the changelog](../../CHANGELOG.md)
for release notes. This is not an assertion of official nixpkgs acceptance.

## Real graphical and NixOS verification

The actual wrapped production executable rendered its frontend in a private
Xvfb/D-Bus session with a temporary XDG profile. Build metadata verified Nix mode,
external updater management and every non-Flatpak policy flag. Screenshot/OCR
assertions require the real email/password/accountless frontend, not merely a
native window title. No user's account or app profile was used, and the WebKit
sandbox was not disabled.

The isolated NixOS VM installed the package in `environment.systemPackages`,
booted to multi-user mode and ran the same graphical smoke as an ordinary user.
It verified no autostart entry was created merely by launching the package and
retained screenshots/build information. The final VM script passed in 106.78 s
using software emulation without changing host KVM permissions or Nix settings.

Issues found and fixed during validation:

- Private D-Bus configuration now comes from the store, not a host `/etc` file;
  bus activation inherits the isolated test XDG profile.
- The development shell explicitly includes librsvg's pkg-config metadata;
  incomplete Nix shells fail clearly instead of attempting host apt/sudo.
- Current VM-driver API replaces deprecated `copy_from_vm` with
  `copy_from_machine`.
- OCR asserts stable rendered form/accountless text, since the default OCR
  segmentation omitted text on the colored sign-in button despite correct
  rendering. Software-emulated VM OCR receives a bounded 60-second subprocess
  limit and a 300-second overall smoke budget; assertions remain identical.

Evidence is included under `evidence/nix-smoke` and `evidence/nixos` in the docs
ZIP; native build metadata and executed build/test logs are preserved separately.
Full-Git WIP checkpoints were saved before/after long production build steps.

## Limits and publication

Windows native execution is unavailable in this WSL session. Windows x64/ARM64,
Linux ARM64 execution, native installers, Scoop lifecycle checks and optional
signed updater outputs remain mandatory remote workflow gates. No new complete
Flatpak builder run, authenticated-service upload, Wayland/hardware-GPU desktop
session, portal screen-sharing/audio test or Home Manager activation is claimed.
The VM proves declarative NixOS package installation and a real X11/WebKit launch,
not every desktop's session integration.

Nix packaging does not claim to fix upstream WebKit bug 323277. The existing Linux
attachment-picker fallback remains documented in [file drops](../file-drops.md).
Application data, sessions, existing tags/assets and user configuration were
preserved. No host NixOS configuration was activated or global installation
changed. No GitHub push, release publication or nixpkgs PR was performed.

After local tagging, publish `master` first and wait for CI, then push `v0.9.0`.
The release workflow verifies tag ancestry and only publishes after all native,
Scoop and Nix gates pass. The normal source/runtime/docs archives are created
only from the clean annotated tag; Windows receives an explicit source-only
build handoff rather than a fabricated executable. Archive checksums and final
tag/commit identities are recorded in the external handoff report.
