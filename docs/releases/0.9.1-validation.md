## Scope

- Global download completion toasts, off by default, with filename-only,
  destination-folder, full-path and partial-path details. Partial paths show
  1–10 nearest parent folders, defaulting to two.
- Persistent, validated preferences; fictional previews; saved-state feedback;
  upgrade defaults and full-backup preservation.
- App-owned local renderer, targeted events, escaped/sanitized text, restricted
  IPC/navigation and no destination injection into hosted services.
- Bounded FIFO notifications with accurate overflow counts, stale-dismissal
  protection, labelled dismissal and selectable/wrapped/scrollable details.
  Timing supports 8/15/30 seconds or persistence, and pauses on hover, keyboard
  focus or backgrounding. The notification never takes focus automatically.
- Native Windows stacking and GTK-specific child-view layout, allocation and
  DPI handling. Linux download failure state is per transfer, and native file
  URIs are decoded before display. Existing vendor IPC/Proton/Windows patches,
  authenticated downloads, destination policies and system notifications remain.

See [download notifications](../download-notifications.md) for settings, privacy
and test commands. No dependencies were upgraded: the direct GTK dependency was
already present transitively. Cargo/npm fixed-output hashes were refreshed for
the changed root package identity and dependency declaration.

## Actual download and graphical verification

Both the native production executable and the wrapped Nix production package
passed all ten isolated real-download cases: disabled defaults; filename, folder,
full and one/two-level partial paths; queue/restack/resize; failed transfer with
successful recovery; cancellation; and hover-paused timed dismissal. File bytes
and SHA-256 are verified, not merely filenames or window titles. Every case
also requires remote notification IPC denial and an unchanged service DOM.

The fixture resets a started TCP transfer for its failure case: WebKit can accept
a normal EOF despite a larger Content-Length. OCR upscales small UI text while
retaining original screenshots and strict path/privacy assertions. GUI tests use
temporary XDG profiles and private D-Bus sessions, never real accounts or the
user's application data. WebKit sandbox and TLS checks remain enabled.

Issues found through actual screenshots and interaction, and corrected:

- GTK child views were vertically packed and lost their fixed positions.
- Fill-size layers could intercept input outside the notification.
- Native surfaces needed bounded overlay bins and post-allocation stacking;
  preferred viewport sizes could leave extra space or clip shorter cards.
- Native resize events preceded GTK content allocation; menu-bar height and
  non-integer CSS/toolkit DPI also required explicit handling.
- Off-screen WebKit renderers could withhold animation frames; DOM-flush
  measurement and initialization of the final GTK surface replace that dependency.

The final Nix package built and passed its 152 Rust tests, desktop/AppStream and
production/distribution validators. `nix flake check` passed on x86_64-linux;
all-system evaluation also passed, without claiming ARM execution. A forced
`nix build .#tauridium --rebuild` passed with identical output:

## Limits and publication

Windows execution is unavailable here: the PowerShell probe failed at WSL's
interop boundary with `UtilAcceptVsock: accept4 failed 110`. Windows native
compile/runtime, WebView2 downloads, installers, ARM execution and optional
signed updater artifacts remain remote/manual workflow checks. No Windows
executable is fabricated. No new complete Flatpak-builder run, authenticated
service-specific download, macOS execution or hardware-GPU/Wayland validation is
claimed. The existing upstream Linux file-drop limitation is unchanged.

The Xvfb download tests select software X11 rendering and disable DMA-BUF only
for their isolated child processes. Installed applications retain the normal
rendering environment. Screen-reader and platform keyboard traversal behavior
still require native desktop verification.

The local Linux runtime ZIP contains a real dynamically linked native executable,
not an AppImage or a bundled Nix closure. Because it was built in the locked Nix
development shell, launch it with that source archive's matching Nix environment;
for Nix/NixOS installation prefer the wrapped package in [the Nix guide](../NIX.md).
The runtime README states these requirements explicitly.

No GitHub push, release publication, Flathub submission or system-wide install
was performed. Publish `master` and wait for the full pipelines, then push
`v0.9.1`. Existing tags are preserved. The post-release Flatpak manifest pins the
immutable release commit without moving its tag.
