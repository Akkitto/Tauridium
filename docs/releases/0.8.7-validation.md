# Tauridium 0.8.7 release validation

Date: 2026-10-03

## Patch scope

- Updated the exact transitive devalue pin from 5.9.2 to 5.9.3, including the locked
  tarball integrity and regenerated Flatpak offline npm sources. The initializer's
  high-severity audit gate remains enabled on both Windows and Linux.
- Fixed the Windows documentation ZIP regression test to verify exact preservation
  of both LF and CRLF bytes. No packaging assertion is skipped or normalized away.
- Isolated the shared disposable packaging Git fixtures from inherited newline settings.

The devalue parser regression also rejects non-string null-prototype keys while
preserving valid objects. See the [upstream patch release](https://github.com/sveltejs/devalue/releases/tag/v5.9.3).

## Passed local gates

`just init` and the canonical clean-tree `just release` workflow completed on Linux
with pinned Rust 1.97.1 and Node.js 24.18.0:

- npm audit: zero vulnerabilities.
- Rust supply-chain policy guard and exact native Rust formatting.
- Locked native and Flatpak Cargo checks and Clippy with warnings denied.
- Svelte: zero errors and zero warnings.
- 544 Python/repository tests, 74 frontend tests, 134 native Rust tests, and
  135 Flatpak-feature Rust tests: 886 tests total.
- Release-invariant and Scoop-template validation.
- Vite frontend and optimized native Tauri production builds.
- Clean Git worktree before and after the workflow.

The focused packaging tests also passed with an inherited `core.autocrlf=true`
configuration; LF and CRLF archive contents are tested explicitly on every platform.
Runtime build information is included in the documentation ZIP evidence directory.

## Platform limits and publication

The user confirmed the preceding Windows worktree fixes work. Windows execution is
not available in this session, so the newly versioned 0.8.7 Windows runtime and its
installer/portable packages are not claimed as locally verified. Windows x64/ARM64,
Linux ARM64, native bundles, Scoop lifecycle checks, and optional updater signing
remain gates of the existing GitHub workflows. No complete 0.8.7 Flatpak builder run
or new authenticated-service upload test was performed here.

Service drop handling is unchanged from 0.8.6. The upstream WebKitGTK native-file-drop
limitation and the Linux attachment-picker fallback remain documented in
`docs/file-drops.md`; this patch does not claim that the engine limitation is fixed.

The source archive contains full Git history and the exact release tag. The explicit
Windows build handoff is source-only, not a Windows executable: use the paired full-Git
source ZIP to run `just init` and `just release` natively on Windows.

Push the updated `master` first and wait for CI, then push `v0.8.7`. The release workflow
verifies that the tag commit is an ancestor of remote `master` and publishes only after
its release gates, native build matrix, and Scoop checks pass. No remote push or GitHub
release publication was performed by this session. Existing v0.8.6 tags and artifacts
are left unchanged.
