# Tauridium 0.8.6 candidate validation

Date: 2026-10-02

## Implemented fix

Every service webview now disables Tauri's native file-drop interception. The main window's
existing setting does not propagate to child webviews. Wry's Windows interception disables
WebView2 external drops, so leaving it active prevents hosted services from receiving files.
The shared service builder covers foreground creation, background preloading, and recreation.

## Passed build and repository gates

The canonical `just release` workflow completed from a clean candidate commit:

- Rust supply-chain policy guard and pinned Rust 1.97.1 formatting.
- Native and Flatpak Cargo feature matrices: Clippy with warnings denied and locked checks.
- Svelte: zero errors and zero warnings.
- 541 Python/repository tests, 65 frontend tests, 134 native Rust tests, 135 Flatpak Rust tests.
- Release-invariant and Scoop-template validators.
- Vite frontend build and optimized native Tauri production build.
- Clean-worktree checks before and after the workflow.

The native executable reports version 0.8.6, production mode, and target
`x86_64-unknown-linux-gnu`. SHA-256:
`ea7dbfb3b443382dbd70d8e903a28157874d5e36c5f2def9ee43ce2a09e9183a`.

## Native-drop gate: not passed

The opt-in test uses an external GTK drag source, real X11 mouse input, and an isolated
local Tauridium profile. It requires trusted browser events and checks the delivered file
names, sizes, and content hashes rather than treating a drop callback as success.

With WebKitGTK 2.52.6, the patched executable receives a trusted drop with URI/HTML types
but an empty file list. This matches [upstream WebKit bug 323277](https://bugs.webkit.org/show_bug.cgi?id=323277).
The upstream restoration is security-sensitive and its proposed fix remains open.
No engine downgrade, security bypass, or privileged remote-page file API was introduced.

Windows application execution is unavailable in this session: WSL interop returns an
executable-format error for PowerShell, and the Windows computer-control JavaScript runtime
is not exposed. A Windows-native production build and real file-drop check remain outstanding.
Live authenticated Proton Mail attachment uploads have not been tested.

The candidate remains distinguishable from a fully verified drag-and-drop release.
