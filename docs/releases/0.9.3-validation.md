# Tauridium 0.9.3 release validation

Date: 2026-10-05. This patch releases the verified Windows documentation-encoding
test fix. It supersedes v0.9.2 without replacing its immutable tag or archives.
Final Git identities, artifact checksums and post-build results are recorded in
the external `tauridium-0.9.3-RELEASE-VALIDATION.md` handoff.

## Scope and regression

All nine repository/generated-file reads in `tools/test_nix_integration.py`
explicitly specify UTF-8. No global Python encoding flag, locale change, permissive
decoder, skipped assertion or application behavior change is introduced.

The CP1252 regression forces the Windows default for unspecified text encodings.
Its negative control reproduces the exact UnicodeDecodeError on real generated Nix
documentation when the encoding is omitted; corrected reads then pass with the
same default. The real Node version generator is executed in temporary fixtures.
The user separately confirmed that compilation now works on the fixed worktree.
That confirmation is not represented as an agent-executed Windows build of v0.9.3.

Release identities and copyable Nix input references are synchronized to 0.9.3.
Cargo/npm dependency hashes were refreshed from real fixed-output fetch results
for the root version change. Dependencies and normal flake inputs are unchanged.

## Evidence and limits

Current evidence uses the `093` suffix: `nix-integration-093/`, `nix-smoke-093/`,
`download-toast-nix-093/`, `download-toast-native-093/`, `nixos-093/`, and release,
CI, Nix build and VM logs. Older evidence and resolved hash-diagnostic failures
remain historical records, not current failures.

Windows native execution is unavailable to the agent at the WSL interop boundary.
Full Windows/WebView2/installer and ARM execution remain remote CI/manual gates.
Local ARM checks are evaluations, not execution. No fresh complete Flatpak-builder,
macOS, hardware-GPU/Wayland, authenticated-service or Flathub-publication run is
claimed. No user profile, Home Manager activation or host system configuration
is changed by the isolated tests.

The Linux runtime ZIP is a real Nix-linked executable, not an AppImage or bundled
Nix closure. Use the matching source checkout's `nix develop` environment; prefer
the wrapped flake package for Nix/NixOS installation. The runtime README explains
these requirements. No Windows runtime is fabricated; a source-only build handoff
is supplied separately.

No GitHub push/publication is performed. Publish master, wait for full pipelines,
then push **v0.9.3**, not the known-broken v0.9.2 tag. Existing tags remain unchanged.
