# Tauridium 1.0.10 release validation

Require canonical native, Flatpak, Nix and system-package quality gates, current
whole-lock advisory checks, native Windows checks and the Arch source-package CI
job before tagging. No dependency assessment expiry is extended by this patch.

The release additionally requires actual x86_64 Arch binary-package installation,
package ownership, real WebKit rendering, nine-phase isolated WAV/Ogg/Web Audio
playback, removal/reinstallation and synthetic profile preservation before
unsigned-artifact verification/signing. Source-package builds use real makepkg,
locked dependency downloads and production Cargo features without the installer
bundler. The native updater plugin and update commands must be absent from the
system-package build; standard native builds retain their updater.

The exact public inventory grows from 32 to 34 assets: separate production Linux
x64/ARM64 system-package ZIPs, included in sealing, scanning, checksums and
provenance. Their ELF target, build policy, binary digest and producer commit are
validated before collection. Existing six updater signatures and publication
approval boundaries remain required. Require exact-tag source/runtime/docs ZIP
integrity and reproducibility. The docs ZIP includes the Arch installation guide.

AUR is not submitted to, and no pacman repository, hosting or signing key is
provisioned. Local source and binary recipes are available from the application
repository. Only Arch x86_64 is advertised; Arch Linux ARM needs separate testing.
Point-in-time clean Arch container results do not establish every desktop or
future rolling release. Execution evidence and reports remain outside the repo.
