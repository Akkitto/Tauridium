# Tauridium 1.0.11 release validation

This patch preserves the existing styled service menu and action handlers while
moving its presentation above native service webviews. The native-menu option
remains available. Changes are confined to menu presentation, native authority
and regression coverage.

Require canonical native, Flatpak, Nix and system-package formatting, lint,
compilation, tests and production builds. Keep current advisory/supply-chain,
artifact inspection, exact-tag packaging, signing and publication gates intact.
No advisory assessment expiry is extended by this patch.

The menu regression must run against a real production executable and synthetic
native service documents, with a fresh profile, private bus and isolated display.
Require all rows visible over the service area, actual pointer actions on the
correct inactive service, keyboard opening/navigation/Escape, click-away,
deactivation, repeated openings, resizing, all three themes and the system-menu
preference. Pure state/geometry tests do not replace this gate.

Both Windows architectures additionally run actual pointer/pixel/UI Automation
checks in the existing clean-host GUI gate. Require unified and classic titlebar
placement, a click above service pixels, correct target persistence, keyboard
focus return, click-away and resize cleanup; the system-menu preference must open
a real OS popup. A fallback must not satisfy the styled-menu assertion.

The Nix production interaction gate runs on both supported architectures. Retain
existing real Settings, notifications, audio, IPC/security, installer and Arch
acceptance tests. macOS remains best-effort; no native macOS execution is claimed.

Source/runtime/docs ZIPs must come from the clean immutable tag, pass integrity
and reproducibility checks and retain the exact reviewed public inventory.
Raw synthetic GUI evidence and full-Git checkpoints remain private and separate.
Execution results and any required owner approvals are recorded outside the repo.
