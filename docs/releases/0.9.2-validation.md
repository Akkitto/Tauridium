# Tauridium 0.9.2 release validation

Date: 2026-10-05. This patch improves Nix integration documentation and executable
examples; it does not change Tauridium's application behavior or add installation
modules/services. Final Git identities, archive checksums and clean-tag packaging
results are recorded in the external handoff under
`/home/akito/src/codex/tauridium-0.8.3-release/deliverables/`.

## Scope

- Direct `packages.${system}` consumption and the locked-package overlay are
  distinguished from module argument forwarding.
- Copyable NixOS `specialArgs`, standalone Home Manager `extraSpecialArgs` and
  embedded `home-manager.extraSpecialArgs` examples explain each module boundary.
- Lexical capture, named `inputs` forwarding, package-set ownership, supported
  architectures, unchanged stateVersion and tested dependency-lock policy are
  covered. Missing-argument errors are diagnosed as consumer wiring errors, not
  package-installation defects.
- Real examples are included in both source and documentation archives; the
  release version generator keeps their immutable input references synchronized.
- Home Manager is pinned in a separate evaluation fixture only. The normal flake
  still has its existing nixpkgs/rust-overlay inputs; no application dependencies
  were upgraded. Cargo/npm fixed-output hashes were refreshed using actual fetch
  mismatches for the new root package identity, not placeholders or bypasses.

See [the Nix guide](../NIX.md) and its linked upstream manuals.

## Real consumer evaluation and graphical checks

`tools/nix_integration.py` evaluated real locked NixOS/Home Manager configurations
for x86_64-linux and aarch64-linux. Each architecture passed ten consumption checks:
direct/overlay/lexical NixOS installation; embedded Home Manager direct/global-overlay
installation; standalone Home Manager direct/overlay/named-input/lexical installation;
and the default/named package alias. Home Manager assertions and activation derivations
were forced, and package membership was compared against the real Tauridium derivation.
These are evaluations, not ARM execution or full consumer host activation tests.

Three negative evaluations per architecture reproduced the exact missing `tauridium`
argument: NixOS, standalone Home Manager, and embedded Home Manager with only NixOS
specialArgs supplied. All six failed as expected; complete diagnostics are retained.
The fixture prohibits lock updates during evaluation. No host configuration was
activated, no profile installed, and no user/account/session data accessed.

The real wrapped Nix executable passed the graphical WebKit smoke and all ten isolated
download notification cases, including failure recovery, cancellation, queue/restacking
and timed dismissal. Downloads were byte/hash checked; remote IPC was denied and
service DOMs remained unchanged. The isolated NixOS VM installed the package and
launched its GUI as an ordinary user; the test script finished in 88.38 seconds with
software emulation. It did not change host NixOS or KVM permissions.

The optimized native Linux executable also passed all ten download cases using
the documented Nix development shell plus the fully supplied headless fixture.
It requires the matching shell's dynamic AppIndicator path; running that Nix-linked
native executable outside its environment is not a portable-runtime test.

Evidence includes `nix-integration-092/report.json`, `nix-smoke-092/`,
`download-toast-nix-092/`, `download-toast-native-092-final/`, `nixos-092/`,
`tauridium-092-ci.log`, and the
`tauridium-092-*-check`, integration, VM and reproducibility logs. Older evidence
and resolved diagnostic attempts are retained; they are not outstanding failures.

## Limits and publication

Windows execution remains unavailable at the WSL interop boundary. Windows native
compile/WebView2/installer verification and ARM execution remain remote CI/manual
checks; no Windows executable is fabricated. No fresh complete Flatpak-builder run,
Flathub submission, macOS, hardware-GPU/Wayland or authenticated-service verification
is claimed. The existing upstream WebKitGTK native-file-drop limitation is unchanged.

The Linux runtime ZIP is a real dynamically linked executable built in the locked
Nix development environment, not a portable AppImage or a bundled Nix closure. Use
the matching source checkout's `nix develop` environment to launch it. Prefer the
wrapped flake package for Nix/NixOS installation; its wrapper supplies desktop
libraries and runtime paths. The archive README explains these requirements.

No GitHub push/publication or system-wide installation is performed. The local tag
is annotated and unsigned; previous immutable tags are preserved. The post-release
Flatpak manifest pin is a separate master commit and does not move the release tag.
Publish master, wait for the full pipelines, then publish v0.9.2.
